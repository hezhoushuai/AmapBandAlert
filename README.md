# AmapBandAlert

把高德地图的导航场景提醒转发到 **小米手环 9 Pro**：转向、到达、拥堵/事故关键词，以及车机版高德广播里的电子眼和超速。

> 当前版本 **0.3.0**。手机端已可构建安装，手环端 P0 走小米运动健康的“应用通知转发”，不依赖第三方手环应用。P1 的“手环实时导航页”尚未在真机验收。

## 先说清楚一个坑

很多教程说“监听高德导航广播”就能拿到导航数据，但 `AUTONAVI_STANDARD_BROADCAST_SEND` 是 **高德车机版 / AmapAuto** 的协议。**手机版高德地图通常不发这个广播**，所以只监听广播的手机 App 在多数人手机上什么也收不到。

本项目的做法：

| 数据源 | 适用 | 能拿到什么 | 状态 |
|---|---|---|---|
| 高德导航**通知**（通知使用权） | 手机版高德 | 转向、距离、道路名、到达/结束、部分提示文字 | **主通道** |
| 高德车机版广播 | 车机版 / 魔改车机版 | 车速、限速、电子眼、转向图标、红绿灯等 | 兼容通道 |
| 关键词扫描 | 手机版高德 | 拥堵、事故、施工、拍照、测速等出现在通知原文里的词 | 实验性，默认关 |

**手机版高德的导航通知通常不包含电子眼字段。** 因此“限速拍照预警”只在车机版广播源可用时才可靠；手机版只能靠关键词碰运气。想要手机版也稳定拿到电子眼，需要后续接入高德导航 SDK（在 App 内导航，见 roadmap），或使用车机版。

## 功能

- 转向提醒：左转 / 右转 / 左前方 / 右前方 / 掉头 / 环岛 / 直行，按可调距离（100–500 米）触发
- 可选临近 50 米二次提醒
- 到达 / 导航结束提醒
- 导航开始提醒（默认关）
- 关键词提醒：拥堵、事故、施工、封路、限行、拍照、测速、电子眼、违章、重新规划
- 车机版广播：电子眼、超速（持续 5 秒）
- 手机端通知默认静音（避免每个路口都响），保留手环震动；需要声音可在系统通知设置里打开
- 前台服务保活、开机恢复、电池优化引导
- 运行日志与“立即读取高德通知”诊断，方便反馈真实通知格式

## 链路

```text
高德地图 App（手机版）
   │  导航通知（前方 200 米右转…）
   ▼
AmapBandAlert 通知监听
   │  文本解析 + 场景判断
   ▼
高优先级通知（每次不同 ID）
   │
   ▼
小米运动健康「应用通知」转发
   │
   ▼
小米手环 9 Pro 显示 + 震动
```

全程本地处理，不联网、不上传导航内容，不需要高德开放平台 Key，也不需要 root / 无障碍 / Xposed。

## 安装与配置

要求：Android 8.0+ 手机、已安装高德地图和小米运动健康。

1. 安装 `AmapBandAlert-debug.apk`。如果你装过 0.2.x 旧版，因为签名不同，可能要先卸载旧版再装（会丢旧设置）。
2. 打开 App，依次完成：
   - **通知权限**：允许通知（Android 13+）。
   - **通知使用权**：系统设置 → 通知 → 通知使用权 → 勾选 `AmapBandAlert`。
   - **电池优化**：允许后台运行 / 忽略电池优化（骑行、锁屏时更重要）。
   - **小米/红米**：设置 → 应用 → `AmapBandAlert` → 自启动允许；省电策略设为“无限制”。
3. 点 **启动监听**。
4. 点 **测试手环通知**，确认手环会震动并显示“手环链路测试”。
5. 在 **小米运动健康** 中开启转发：
   - 设备 → 手环 → 应用通知 / 通知设置 → 找到 `AmapBandAlert` 并开启；
   - 关闭“通知过滤/智能隐藏”，或将该应用设为“全部通知”；
   - 确认手环的通知震动没有关闭。
6. 在高德地图开始导航，观察 App 状态卡和运行日志。
7. 如果手环没反应：先在 App 里点“立即读取高德通知”，看日志里有没有高德通知原文；再检查小米运动健康的转发开关。部分运动健康版本会过滤静默通知，可到系统设置把 `AmapBandAlert` 的“导航场景提醒”渠道改成响铃/重要后再试。

## 真机测试建议

先在安全、可停留的位置用高德的**模拟导航**或短途步行导航测试，不要一边骑车一边调权限。

建议反馈以下信息（不要发真实住址/路线）：

- 手机型号、系统版本（HyperOS / MIUI / 其它）
- 小米运动健康版本、手环固件
- App 版本（0.3.0）
- “立即读取高德通知”日志里的通知原文
- 手环是否震动、是否显示、显示内容

## 已知限制

- **手机版高德的通知文字没有稳定格式**。高德升级后解析可能需要调整；日志保留了原文，便于修。
- 手机版高德通常**不提供电子眼/限速数据**，所以电子眼开关对手机版基本无效；关键词模式也不保证能抓到。
- 小米运动健康对通知转发有去重和过滤策略，不同系统版本表现不同；本项目用不同 notificationId 降低被吞的概率，但不能 100% 保证。
- 手环只显示通知文本，不能显示实时箭头/剩余里程；这是 P1 手环快应用要解决的问题。
- 未在真机验收。当前 APK 只做了编译、资源、签名和解析逻辑检查。
- 车机版广播的 `CAMERA_TYPE` 枚举没有统一文档，本项目对非 0 类型统一提醒，可能包含非限速类电子眼。

## 构建

仓库根目录：

```bash
# 需要 JDK 17+ 和 Android SDK（platform 34、build-tools 34）
export ANDROID_HOME=/path/to/android-sdk
bash scripts/build_no_gradle.sh
# 输出 AmapBandAlert-debug.apk
```

也可以使用 GitHub Actions：推送到 `main` 后，工作流会先跑解析器测试，再构建并把 APK 推到 `apk-delivery` 分支。

签名使用仓库内固定的 debug keystore（`android-app/keystore/debug.keystore`，密码 `android`），这样后续版本可以覆盖安装，也方便 P1 手环 RPK 使用同一套证书。它只适合个人测试，不要用于正式发布。

## 路线图

- **P0（当前）**：通知监听 → 场景提醒 → 小米运动健康转发 → 手环震动
- **P1**：手环 Vela 快应用，经小米互联 SDK 接收手机推送，显示转向箭头、距离、道路名；手机与手环同包名、同签名
- **P2**：手机版可靠的电子眼数据（高德导航 SDK 内置模式，或无障碍/音频识别方案），以及红绿灯、车道线等更丰富场景

P1 涉及小米穿戴互联 SDK 和 RPK 签名，已在参考项目中验证可行，但本项目尚未在真机跑通，不在此版本交付。
